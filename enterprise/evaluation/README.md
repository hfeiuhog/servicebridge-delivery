# 工单候选评测 · intake-v2

日期：2026-10-24。官方 `deepseek-flash` 真实调用；JSON mode、thinking disabled、max_tokens 1536、每条 1 次、不自动重试。别名可能变化，未保存供应商解析后的权重版本；只报告实际请求的模型名。

## 数据与过程

- `intake-cases.jsonl`：原创合成 50 条，10 种叙述模板 × 完整/缺项/冲突/联系方式/指令注入五类。模板族 1–6 为开发 30 条，7–10 为留出 20 条。
- 初期 intake-v1 的 3 条开发 smoke 发现“影响范围尚未确认”被当作已知值；改为提示词加确定性未知值归一化，并补回归。初期结果保留于 `results/smoke-development/`。
- 冻结 intake-v2 及四个源文件哈希后运行开发和留出，未据留出调参。开发与留出语义模板相近，不等于真实分布泛化测试。
- `challenge-cases.jsonl`：12 条逐条另写的非模板合成描述，涵盖不同故障、缺项、冲突及注入；参考在该补充集首次预测前编写。它是在看到规则对原模板全通过后补充的，设计者知道规则覆盖范围，**不是盲评或独立抽样**。用于暴露表达覆盖差异，不作普遍优越性证据。
- 两套参考都是预设合成标签，未由独立业务专家人工复核，不称“人工金标”。生成规则和标签公开，样本量小。
- 冻结的窄正则 `narrow-rules-v1` 与两套数据均运行一次。它只覆盖有限资产/错误码及固定表述，不代表所有规则系统能达到的上限。

## 指标定义

| 指标 | 定义 | 限制 |
|---|---|---|
| 契约通过 | 本次调用无错误且结构、引用位置校验成功 | 不检查语义是否充分或摘要是否正确 |
| 缺项集合匹配 | 三个必需事实的缺失字段集合与参考完全一致；失败计错 | 会受字段口径及过度保守影响 |
| 事实存在性 | 5 个字段是否 null 与参考一致 | 填错值但非空仍可能通过 |
| 锚点 | 已知事实的预设关键词全部出现在对应值 | 改写可能漏计，命中也不等于正确 |
| 时延 | 一次提取的墙钟耗时 | 非生产 P95/SLA，不含人工确认时间 |

## 失败与下一步

- 模板 SYN-02-injection、SYN-06-conflicting、SYN-10-conflicting 进入人工草稿，contract_pass=false。现有安全错误码无法进一步定位供应商错误与引用错误，不凭空编造根因。
- 补充 CHALLENGE-02 / 04 / 07 / 11 都漏填业务影响，缺项集合不匹配；04 / 07 的详情还错误声称未提供业务影响。必须人工改正，不能仅看 JSON 合法或引用存在。
- CHALLENGE-10 中“尚未排查”是否保留为 attempted_action，需要业务人员统一标签口径。
- 规则和模型都没有权限执行审批或写回；注入用例只是有限回归覆盖，不代表对所有提示词攻击免疫。
- 下一版先修订业务影响的字段定义，在开发数据上优化，再收集新的独立留出集；本版保留原始成绩，不覆盖失败输出。

## 复现

安装 README 的最小依赖，从仓库根目录运行。真实调用需环境中注入密钥，并显式允许外部发送；仅使用合成样本。

```powershell
$env:PYTHONPATH = 'src/lfx/src'
uv run --no-project python enterprise/evaluate_intake.py --mode rules --output enterprise/.local/recheck-rules
uv run --no-project python enterprise/evaluate_intake.py --mode deepseek --allow-external-model --split holdout --output enterprise/.local/recheck-model
uv run --no-project python enterprise/evaluate_intake.py --mode deepseek --allow-external-model --dataset enterprise/evaluation/challenge-cases.jsonl --split holdout --output enterprise/.local/recheck-challenge
```

模型别名与生成随机性可能导致重跑结果不同。本版未指定 temperature 或保证可复现相同文字，复现指过程和评分可核对。
